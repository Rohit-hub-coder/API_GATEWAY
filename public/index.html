✈️ Flights & Search Service (:3000)

Scheduled Flight Catalog with Concurrency-Safe Seat Inventory

₹10,000
💡 Interview Talking Point (Seat Consistency):

When a booking request arrives, seat count is atomically decremented at the database level (UPDATE Flights SET totalSeats = totalSeats - N WHERE id = ? AND totalSeats >= N). The UI always re-queries /api/v1/flights/flight/:id after book or cancel to animate the real value from disk.

🎫 Booking Service (:3002)

Transactional Outbox & Ticket Management

0 Bookings
💡 Interview Talking Point (Transactional Outbox):

Bookings and events are inserted in a single ACID transaction into Bookings and Outboxes tables. A background poller reads unpublished outbox events and pushes them to RabbitMQ. If RabbitMQ is down, the booking still succeeds and events queue safely in MySQL.

📐 High-Level Microservice Topology Reference

Database-per-Service Architecture
1. API Gateway (:3004)

Reverse proxy with rate limiting, circuit breaker, and local JWT signature validation (avoids hot-path auth network hops).

2. Flight Service (:3000)

Owns flight_search_db_dev schema. Manages flights, airplanes, and atomic inventory seat capacity.

3. Booking Service (:3002)

Owns booking_db_dev. Dual-writes booking record and outbox event inside a single ACID database transaction.

4. Reminder Service (:3003)

Owns reminder_db_dev. Asynchronous AMQP consumer with idempotency check, sending confirmation emails via Nodemailer/Ethereal.
